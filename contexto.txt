── DESCRIPCIÓN GENERAL ─────────────────────────────────────────────────────────

INTESIS es un sistema de gestión empresarial (ERP lite) desarrollado en PHP 8
con MVC propio (sin framework). Corre sobre XAMPP en Windows con PostgreSQL 17.
Gestiona inventario, compras y ventas para múltiples empresas desde una sola
instalación (multi-empresa por sis_empresa_id).

Entorno local:
  URL:      http://localhost/intesis
  BD:       PostgreSQL 17, base de datos "intesis"
  Ruta:     C:/xampp/htdocs/intesis
  .env:     APP_URL=/intesis, DB_HOST=127.0.0.1, DB_PORT=5432


── ESTRUCTURA DE ARCHIVOS ───────────────────────────────────────────────────────

/index.php                  Punto de entrada único. Carga todos los require_once
                            y llama a Aplicacion::iniciar()->ejecutar().
/src/Nucleo/
  Aplicacion.php            Instancia todos los modelos y controladores, los pasa
                            al Enrutador vía constructor (DI manual).
  Enrutador.php             Mapea rutas (método + URL) a métodos de controladores.
                            Rutas hardcodeadas con if/return, sin regex.
  ControladorComun.php      Trait con: exigirSesion, exigirPermiso, responderJson,
                            redirigir, esSuperusuario, registrarErrorCrud.
  ConexionBaseDatos.php     Singleton PDO pgsql. Se accede via ->obtener().
  Vista.php                 Renderiza vistas PHP incluyendo plantillas.
  Sesion.php                Gestión de sesión PHP nativa.
  Configuracion.php         Lee .env, expone obtener('CLAVE', 'default').
  RegistroErrores.php       Escribe excepciones en /log_errores/.

/src/Controladores/         Un archivo por controlador. final class + use ControladorComun.
/src/Modelos/               Un archivo por modelo. final class. Solo SQL via PDO.
/src/Vistas/                Carpetas por módulo: autenticacion, sistema, inventario,
                            compras, ventas, panel, plantillas, errores.
/src/Vistas/plantillas/     encabezado.php, menu_lateral.php, pie.php
                            (incluidos con require desde cada vista).

/migrations/                Archivos .sql idempotentes. Nombrados YYYYMMDD_HHMM_desc.sql
/publico/                   CSS, JS, imágenes públicas.
  /publico/js/sistema.js    JS global: DataTables en .tabla-intesis, SweetAlert,
                            validaciones RUC/cédula Ecuador.
/almacenamiento/sesiones/   Archivos de sesión PHP.
/log_errores/               Logs de excepciones.


── BASE DE DATOS: TABLAS PRINCIPALES ───────────────────────────────────────────

SISTEMA
  sis_empresa           Multi-empresa. Toda tabla de negocio tiene sis_empresa_id.
  sis_usuarios          Usuarios del sistema.
  sis_usuario_empresa   Relación usuario-empresa-perfil.
  sis_perfil            Perfiles de acceso (ej: SUPERUSUARIO).
  sis_menu              Menús (tipo M) y acciones/botones (tipo B) con URL.
  sis_perfil_permisos   Qué acciones puede hacer cada perfil por empresa.
  sis_estado            Catálogo de estados por módulo+entidad+código.
                        (sis_estado_modulo, sis_estado_entidad, sis_estado_codigo)
  sis_tipo_documento    Tipos de doc por módulo (FACTURA_VENTA, NOTA_VENTA, PROFORMA…).
  sis_secuencias        Numeración automática por empresa+tipo+establecimiento+punto.
  sis_iva               Tabla de porcentajes de IVA por empresa.
  sis_mensaje_sistema   Textos de alertas configurables para el frontend.

INVENTARIO
  inv_bodega            Bodegas por empresa.
  inv_bodega_usuarios   Asignación usuario-bodega (una predeterminada).
  inv_categoria         Categorías de productos.
  inv_marca             Marcas de productos.
  inv_producto          Productos/artículos.
  inv_stock             Stock disponible por empresa+bodega+producto.
  inv_kardex            Movimientos de inventario (ENTRADA, SALIDA, VENTA, AJUSTE_IN…).
  inv_movimiento        Cabecera de movimientos internos.
  inv_movimiento_det    Detalle de movimientos internos.
  sis_archivos          Imágenes/archivos de productos.

COMPRAS
  com_proveedor         Proveedores.
  com_codigo_proveedor  Códigos del proveedor para cada producto.
  com_documento         Documentos de compra (facturas de proveedor, XML SRI).
  com_documento_det     Detalle de documentos de compra.

VENTAS
  ven_cliente           Clientes. Tipos: R=RUC, C=Cédula, P=Pasaporte, O=Consumidor Final.
  ven_lista_precio      Listas de precios por empresa.
  ven_lista_precio_det  PVP por producto en cada lista.
  ven_documento         Cabecera de documentos de venta (facturas, proformas, notas).
                        Campos clave:
                          sis_tipo_documento_id  → tipo (FACTURA_VENTA, NOTA_VENTA, PROFORMA)
                          sis_estado_id          → estado (CREADA, ANULADA, AUTORIZADA, ERROR)
                          ven_documento_proforma_id → si viene de proforma
                          ven_forma_pago_id      → forma de pago
                          ven_documento_numero   → número generado por sis_secuencias
  ven_documento_detalle Líneas del documento (producto, cantidad, precio, IVA…).
  ven_forma_pago        Catálogo de formas de pago por empresa.
                        ven_forma_pago_calculadora CHAR(1) S/N → muestra calculadora de cambio.
  ven_cxc               Cuentas por cobrar generadas por facturas a crédito.

Estados de VEN_DOCUMENTO (módulo VENTAS, entidad VEN_DOCUMENTO):
  CREADA, ANULADA, AUTORIZADA, ERROR

Tipos de documento módulo VENTAS:
  PROFORMA       → cotizaciones, no descuenta stock
  FACTURA_VENTA  → factura electrónica SRI, descuenta stock
  NOTA_VENTA     → nota de venta interna, descuenta stock, NO va al SRI

── PATRONES DE CÓDIGO ESTABLECIDOS ────────────────────────────────────────────

CONTROLADOR (estructura estándar):
  - Constructor recibe: Vista, Sesion, Modelo, MenuModelo, MensajeSistemaModelo,
    Configuracion, RegistroErrores (+ extras si los necesita).
  - Métodos de vista (GET): listar(), nuevo(), editar()
  - Métodos de acción (POST/JSON): guardar(), anular()
  - Métodos JSON de apoyo: detalle(), buscarCliente(), productos(), etc.
  - Helpers privados: normalizarCabecera(), validarCabecera(), normalizarLineas(),
    validarLineas(), obtenerPermisos()

MODELO (estructura estándar):
  - Constructor recibe: ConexionBaseDatos (+ SecuenciaModelo si genera números).
  - Métodos públicos: listar(), buscar(), crear(), actualizar(), anular()
  - Lookups públicos: listarFormasPago(), listarEmpresasActivas(), listarIva()
  - Helpers privados: bloquearDocumento(), obtenerBodegaId(), obtenerTipoDocumentoId(),
    obtenerEstadoId(), validarStock(), insertarLineasYDescontarStock(),
    descontarStock(), revertirStockYKardex(), generarCxcSiAplica(), pdo()

VISTA (estructura estándar):
  - Inicio: $claseCuerpo, require encabezado.php, leer $appUrl y $appNombre del .env.
  - Estructura HTML: navbar, sidebar (menu_lateral.php), main → card cabecera →
    card detalle → totales.
  - Fin: require pie.php, bloque <script> con IIFE.
  - Modales al final del body antes del script.
  - JS con fetch() para guardar; SweetAlert2 para confirmaciones.

FORMULARIOS (patrón cabecera + detalle):
  - Card cabecera: título + botones [Cancelar][Guardar] en el card-header.
  - Card detalle: título + botón [Agregar línea] en card-header.
    Tabla con columnas: #, Código, Descripción, Stock, Cant., Precio, Desc%, IVA, Total, Eliminar.
  - Totales: tabla pequeña alineada a la derecha.
  - Modal confirmación (si aplica): muestra Total, y si forma_pago tiene
    calculadora='S' muestra Valor recibido + Cambio en una sola fila.

RESPUESTA JSON estándar:
  { "ok": true|false, "codigo": "OK|ERROR_...", "mensaje": "...", "data": {} }


── FLUJO DE UN DOCUMENTO DE VENTA (FACTURA / NOTA DE VENTA) ───────────────────

1. Usuario llena formulario (cliente, forma de pago, tipo doc, líneas).
2. Clic en Guardar → si forma_pago.calculadora='S' muestra modal con calculadora.
3. Clic en Facturar → fetch POST /ventas/facturas/guardar con payload JSON.
4. FacturaControlador::guardar() normaliza y valida datos.
5. FacturaModelo::crear():
   a. Inicia transacción.
   b. Obtiene número de secuencia (SecuenciaModelo).
   c. Valida stock (throw si insuficiente).
   d. INSERT ven_documento con sis_tipo_documento_id según tipo (FACTURA_VENTA o NOTA_VENTA).
   e. INSERT ven_documento_detalle por cada línea.
   f. Descuenta inv_stock + INSERT inv_kardex tipo='VENTA'.
   g. Si forma de pago es Crédito → INSERT ven_cxc (cuenta por cobrar).
   h. Commit.
6. Responde JSON {ok:true} → frontend redirige a /ventas/facturas.

Al ANULAR:
  - Solo si estado = CREADA.
  - Revierte stock (incrementa inv_stock + kardex tipo='AJUSTE_IN').
  - Cambia estado a ANULADA.
  - Cancela ven_cxc si existía (estado='A').
